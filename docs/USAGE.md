# Usage

See README.md, fixture/FIXTURE.md, docs/RECORD.md (recorded keys) and docs/TUNING.md (factors).

## Prerequisites

Python 3.11+, bash, git, Docker with Docker Compose 2.24 or newer and one agent client
(Clients below), here or on a remote host over ssh (clone this repo there, fixture/FIXTURE.md).
Ports 16686 (Jaeger query) and 8016 (flagd OFREP) must be reachable. `fixture.env` (copy of
`fixture.env.example`) holds the fixture location, `RUNS_DIR`, API keys, the Goose settings (`GOOSE_PROVIDER`, `GOOSE_MODEL`: read by `make measure`, `make smoke` and as the grader's fallback) and the Codex command.

> [!WARNING]
> Every trial is one paid agent run: 20 for 10 per arm with two arms.

## Before you start

1. On a fresh Ubuntu, install make and Docker, then log in again so the `docker` group applies (groups are read at login; `exit` the shell or ssh session and come back):
   ```bash
   sudo apt-get update && sudo apt-get install -y make git curl
   curl -fsSL https://get.docker.com | sh
   sudo usermod -aG docker "$USER"
   ```
   `make measure` also needs Go, the version in the `go.mod` of your Jaeger checkout.
2. Start the fixture: 22 containers (23 with Phoenix), about 2.9 GB RAM, 6 busy cores. `make setup` runs `make preflight` first, pulls the pinned Goose image next to the demo's, and `make up` waits up to 10 minutes for the fixture (agent settings are not needed); Phoenix takes one to two more, and traces show after a few minutes of load. Then set `OPENROUTER_API_KEY` in fixture.env (`GOOSE_PROVIDER` and `GOOSE_MODEL` default to the Jaeger AI Assistant demo's `openrouter` and `nvidia/nemotron-3.5-lightning:free`) and run `make smoke` (`DRY=1` stops after the dry run), one paid trial and a dry run first, or `make smoke CLIENT=claude` on the Claude Code CLI (`CLIENT` in fixture.env sets the default). Pre-flight checks that a key is set, not that the provider accepts it or knows the model; the first trial is that check. A free OpenRouter key covers a few smokes a day; `make measure` needs credits on the key or a paid model.
   ```bash
   make setup
   ```

## The experiment file

`harness/experiments/<name>.json` is the complete configuration of a batch; copy one for your
own runs. `smoke-paymentfailure.json` is the exception: a template without `run.client`, `provider` or `model`,
which `bench.py run` refuses; `make smoke` fills them in (Goose from `GOOSE_PROVIDER` and `GOOSE_MODEL`, or
`CLIENT=claude` with `CLAUDE_MODEL`, or `CLIENT=codex` with `CODEX_MODEL`) and runs the git-ignored `smoke-run.json` it writes. An experiment named `smoke-*` is a check, not a record: its batch is never copied to `records/` and `verify` skips it. Every key is required except `run.client_version`, `run.bill_api_key`, and `run.max_budget_usd` for `goose` and `codex`; unknown keys are refused. Below is the
`goose` pair file `make measure` writes, with the long `hypothesis` elided and placeholders in angle brackets:

```json
{
  "name": "measure-recommendationCacheFailure-<head sha>",
  "version": 2,
  "scenario": "recommendationCacheFailure",
  "hypothesis": "...",
  "run": {
    "client": "goose",
    "provider": "openrouter",
    "model": "<full model id of the provider>",
    "effort": null,
    "max_turns": 30,
    "n_per_arm": 10,
    "seed": null
  },
  "arms": {
    "baseline": {"prompt": "neutral", "image": "jaeger-mcp-evals/jaeger:measure-base-<base sha>", "tools": true},
    "variant": {"prompt": "neutral", "image": "jaeger-mcp-evals/jaeger:measure-change-<head sha>", "tools": true}
  },
  "baseline_arm": "baseline",
  "thresholds": {"fisher_p_max": 0.05},
  "status": "generated by measure.sh <date>"
}
```

The `claude` and `codex` shapes are under Other clients.

| Key | Values | Meaning |
|---|---|---|
| `name`, `version`, `scenario`, `hypothesis` | string, `2`, a `harness/scenarios/` name, text | records land in `records/<name>/`; the hypothesis states what the thresholds test |
| `run.client`, `run.provider` | `goose` `claude` `codex` (`cli` is read as `claude`); `anthropic` `openrouter` or `null` | Clients below; provider is required for goose, null for the others |
| `run.model`, `run.effort` | full id; `low` `medium` `high` `xhigh` `max`, or `null` for goose (no effort sent) | the id is sent unchanged; an alias is warned, not pinned |
| `run.max_turns`, `run.max_budget_usd` | positive integer, positive number | CLI turns (claude), Goose turns (goose), tool calls (codex); the budget is the cli's per-trial cap, required for claude, optional and without effect for goose and codex (recorded as null when absent) |
| `run.n_per_arm`, `run.seed`, `run.client_version` | integer, integer or `null`, optional string | trials per arm; `null` draws and records a seed; when set, the batch refuses unless the client reports that version (exact re-runs only) |
| `arms.<arm>` | `prompt`, `image`, `tools` | a `harness/prompts/<prompt>.txt` name; the Jaeger image it needs; `false` removes the MCP server |
| `baseline_arm`, `thresholds`, `status` | arm or `null`; object; text | what `judge.py` compares against; see Thresholds; a batch refuses while `status` contains `DRAFT` |

> [!IMPORTANT]
> Any edit changes the file's sha256. Record why in `status`, and note it in CHANGELOG.md if earlier batches stop being comparable.

### Clients

- `goose`, the reference client and the default for `make smoke` and `make measure`: Goose v1.57.0 via `harness/goose_client.py`, in the image the Jaeger AI Assistant demo pins (`IMAGE` in that file, recorded as `goose_image`), started through the demo's `goose-without-extensions.sh` (`harness/goose/`), one container per trial, removed when the trial ends or is stopped. Needs Docker, the image (pre-flight prints the `docker pull` line), `run.provider` `anthropic` or `openrouter` and that provider's key (`ANTHROPIC_API_KEY` or `OPENROUTER_API_KEY`) in fixture.env; the key reaches only this client, by name. `make measure` takes provider and model from `GOOSE_PROVIDER` and `GOOSE_MODEL`, and `--client claude` (or `CLIENT=claude` in fixture.env) runs it on the Claude Code CLI instead (`bash harness/measure.sh <checkout> <scenario> --client claude`). `make smoke` and `make measure` write `run.effort` null for goose, so no effort is passed, as in the demo; an experiment file that sets `run.effort` has it sent as `GOOSE_THINKING_EFFORT` (`xhigh` is Goose's alias of `max`). Goose's own `load_skill` tool (two built-in skills, no network) is allowed and each call is listed under Client limits, since on a skill experiment it can stand in for Jaeger's `read_skill`. Goose calls Jaeger's shared MCP endpoint, as the other clients do; the demo's gateway path (a chat turn through `/api/ai/chat` with the UI tools) is not measured. On Docker Desktop (macOS, Windows) the container's host network is the Docker VM's, so the client drops `--network host` and sends a loopback MCP host to `host.docker.internal`; keep `FIXTURE_HOST=localhost` there.

### Other clients

- `claude` (Claude Code CLI, called `cli` in records before 2026-11-23): the logged-in `claude` (install: `curl -fsSL https://claude.ai/install.sh | bash`; it puts `claude` in `~/.local/bin`, so open a new shell or add that directory to PATH; log in once: `claude`) via `harness/claude_client.py`. Every published result ran on it; [records/inputs/skill-callee-down-cli55.json](../records/inputs/skill-callee-down-cli55.json) is the shape: `"client": "cli"` (read as `claude`), `"provider": null`, `"model": "claude-sonnet-5-5"`, and optionally `run.client_version` (`"2.1.285"` there) and `run.bill_api_key`. No API key is in its environment unless `run.bill_api_key` is true (client `claude` only): then the claude agent and the claude grader bill `ANTHROPIC_API_KEY` instead of the login. `GRADER_CLIENT=claude` in fixture.env grades on it (Pins, cost and what to attach).
- `codex`, experimental: `codex` (or `CODEX_BIN`) via `harness/codex_client.py`, `"provider": null`; MCP only, read-only sandbox, stops after `max_turns` tool calls. `make smoke CLIENT=codex` runs one trial on `gpt-5.6-terra` (log in once with `codex login`).

## Run a batch

1. Dry run, from the repository root.
   ```bash
   make run EXPERIMENT=<name or path> DRY=1
   ```
   > [!TIP]
   > The dry run is free: a read-only pre-flight that prints the plan and seed, never flips the flag or calls a model.
   The pre-flight prints numbered stages (`[1/4] Agent and grader`, `Scenario`, `Jaeger under test`, `Demo`; a real run adds `[5/6] Fault on` and `[6/6] Evidence`), each with the reason it exists and one `ok`, `FAIL` or `WARN` line per check. A `FAIL` stops the run, comes with a `fix:` line where a first-time runner is likely to land, and is followed by one `bench: ABORT` line. A `WARN` (the scripted evidence check failed) lets the trials go on.
   Run `smoke-run.json` (written by `make smoke`), a file under `records/inputs/` (`claude` only), or your own copy of an experiment file.
2. Run (`FIRST=1`, `--first-only` for the script, runs one cell): flips the flag and confirms it through OFREP, waits for fresh fault traces, runs the cells shuffled (a cell still running after 30 minutes is killed and counts as a failed cell), restores the flag, scores. Output goes to `$RUNS_DIR/<scenario>/batch-<UTC>/`; its records, never trajectories, are copied to `records/<name>/`.
   ```bash
   make run EXPERIMENT=<name or path> [FIRST=1]
   ```
3. Verify: re-scores every `stream.jsonl` except those of smoke batches; fails on a disagreeing verdict, any INVALID or LEAK run, an answer with no cached grade, a trial that failed to score in its run (one `ERROR` line: discard that batch), or a stale `records/INDEX.md` (`run` and `bench.py index` rewrite it).
   ```bash
   make verify
   ```
4. Judge the baseline and variant batches (`$RUNS_DIR` or `records/` copies): PASS or FAIL per threshold, then `EXPERIMENT PASS` or `EXPERIMENT FAIL`; writes `records/<name>/RESULT.md`.
   ```bash
   python3 harness/judge.py <baseline_batch_dir> <variant_batch_dir>
   ```
5. Pack: writes `dist/<name>-trajectories.tar.gz` and `records/<name>/trajectories.sha256`; refuses (exit 1) on a file that would publish the fixture host, ssh user, home directory, key, base URL or session id.
   ```bash
   python3 harness/bench.py pack <name>
   ```

> [!WARNING]
> Step 2 spends money: one agent trial per cell, plus one grader call per new mechanism answer.

`run` exits 0 done; 1 bad file or pre-flight failure; 4 aborted after 3 consecutive cell failures, or every cell that ran
failed (the client's own error is printed under each failed trial; a failed cell scores FAIL);
6 interrupted or incomplete; 7 a trial failed to score (a grader timeout or invalid label; see the error rows in
`scores.jsonl`), so `measure.sh` stops before judging.

> [!CAUTION]
> Exit 5 means the flag was not confirmed back at its default after polling OFREP for 10 seconds. Check the fixture before anything else; this code wins over 4 and 6.

A batch aborts before the flag flips on:

| Cause | Detail |
|---|---|
| No arm matches | only arms whose `image` equals `docker inspect jaeger` run; run other images as separate batches |
| Instructions mismatch | an arm whose image record has an `instructions` key must serve the MCP `instructions` string equal (trimmed) to that file under `harness/experiments/instructions/`; absent or null is recorded only (`instructions_sha256` in the manifest) |
| Failed gate | leak scan, readiness or sandbox probe (claude); `status` has `DRAFT`; wrong client version; mean `bi` of `vmstat 5 3` over 50000 (a demo host without vmstat, such as macOS, gets a WARN instead) |

The oracle (docs/SCENARIOS.md) runs after the flag flips and only warns; it never aborts a batch.

## Pins, cost and what to attach

- Agent model: `run.model`, by full id. With the `claude` client the batch stops after a trial whose stream reports another model (`model_asserted` in scores.jsonl), and the pair is discarded.
- Client version: optional `run.client_version`, for an exact re-run of a published result. Pre-flight aborts before anything is touched only when the experiment file sets it and the chosen client (`claude`, `codex` or the Goose image) reports another version; `make measure` does not write it. Without it the version is recorded and `judge.py` refuses a pair whose arms differ.
- The harness does not pin the Claude CLI, it checks it. Every Claude CLI call it makes (trials, the sandbox probe, the grader) runs with `ENABLE_TOOL_SEARCH=false` and `DISABLE_AUTOUPDATER=1`; stage 1 prints the installed version; `judge.py` refuses a pair whose trials ran on different client versions (exit 2, both versions named) and, for batches that recorded none, says "client version not recorded" and judges. Keep each pair on one client.
- Before spending, stage 1 prints `expected cost about X USD per arm of n trials (recorded max Y per trial, cap Z)`, the cap shown only for the `claude` client, X being n times the recorded median, from the recorded trials of the scenario on the model (`records/**/scores.jsonl`), or `expected cost unknown`. With the `claude` client it WARNs, without stopping, when the recorded max is at least half of `run.max_budget_usd`: such a trial can be cut off and return no verdict. There is no turn warning: the CLI's `num_turns` is not what `--max-turns` counts (a trial recorded 40 turns under `--max-turns 30` and ended success). Multiply by the number of arms the batch runs.
- Grader: `GRADER_CLIENT` in `fixture.env`, empty (the default: `claude` for a Claude agent, else `goose`), `goose` or `claude`. `goose` runs `goose run` in the same pinned image as the agent, no extensions, with `GRADER_PROVIDER` and `GRADER_MODEL`, falling back to `GOOSE_PROVIDER` and `GOOSE_MODEL` (by default `openrouter` and `nvidia/nemotron-3.5-lightning:free`, from fixture.env.example); pre-flight refuses without a provider, its key and a model. `claude` runs `GRADER_MODEL` (default `claude-fable-5-1`, the only grader model validated, and on the claude grader only) through `GRADER_BIN` (default `claude`, any command that accepts the Claude Code CLI's `-p` arguments, `--version` and `auth status`). Stage 1 checks a `claude` grader's login (`auth status`) unless `run.bill_api_key` bills the key, and prints one line naming the agent model and the grader model, as a WARNING when they differ or when the grader is not the validated one (`claude` on `claude-fable-5-1`): The grader decides every mechanism score: use the agent's model or a stronger reasoning model. Re-scoring (`verify`, `band`, `judge`) reads grades by the grader the batch's manifest recorded, so changing the setting never leaves an old batch ungraded; grades from different graders are not comparable.
- Jaeger: `make measure` runs the Jaeger built from your checkout (main lineage); the fixture itself boots the pinned release quay.io/jaegertracing/jaeger:2.23.0 and no other release is used or tested. `bench.py` reads traces from Jaeger's `/api/v3/traces` endpoint.
- Cost of the published pair (skill-callee-down-cli55, 10 trials per arm, sum of `cost_usd` in scores.jsonl): baseline 0.77 USD, variant 2.77 USD. Wall time from the first cell start to the last cell end in cells.jsonl: about 4.5 minutes and 8 minutes. The grader adds one call per trial.
- For a pull request, attach `RESULT.md` (from `judge.py`) and the batch directory `bench.py run` copied to `records/<name>/`.

## Measure a change

`harness/measure.sh <jaeger-checkout> <scenario> [--base <ref>] [--n <per-arm>] [--client goose|claude|codex] [--yes] [--dry-run]` (or `make measure JAEGER=<checkout> SCENARIO=<name> [CLIENT=] [N=] [BASE=] [DRY=1] [YES=1]`: the same options in upper case) answers "does my Jaeger commit change the pass rate on this scenario?". It refuses a checkout with uncommitted changes, takes HEAD as the change and `--base` as the base when given, else `merge-base HEAD upstream/main` (else `origin/main`), builds both images on the fixture (`fixture/build-image.sh`, from a temporary worktree), writes `harness/experiments/measure-<scenario>-<head sha>.json` before any trial, asks for a y/N, commits the file signed off (on N nothing is committed; the two image records stay local, and each batch's manifest records the image tag, id and Jaeger commit), then for each image swaps the fixture's jaeger (`fixture/swap-jaeger.sh`), waits 5 minutes for traffic, runs the batch, and restores the image it found. It ends with `judge.py`: `fisher_p_max` 0.05 on PASS counts.

Cost: 2 x n trials (default 10 per arm). With `--client claude` the model is `CLAUDE_MODEL` (claude-sonnet-5-5), measured at 0.4 to 2.4 USD of agent time per 10-trial arm plus a grader call per trial; on Goose the cost depends on `GOOSE_MODEL` (stage 1 of `bench.py` prints the expected cost). `--dry-run` checks and prints every step without building, swapping or running. With `claude`, `make measure` bills `ANTHROPIC_API_KEY`, not your claude.ai login, while `make smoke` uses the login. An unknown scenario name prints the list of scenarios. The builds need Go on this machine (the version in Jaeger's go.mod). Each build prints a start line and an end line and keeps the rest in `/tmp/variant-build-<name>-<sha>/build.log`, shown (last 20 lines) when a build fails; a successful build removes that directory and the fixture's `~/variant-build/<name>`.

Each build leaves an image on the fixture. List them with `docker image ls jaeger-mcp-evals/jaeger` and remove one with `docker image rm <tag>` (not the one the fixture runs).

For a pull request attach `records/<experiment>/RESULT.md` and the two batch directories under `records/<experiment>/`.

## Stop and restart

- `make down` stops the containers and keeps them. Jaeger's store is in memory, so its traces are lost; Phoenix keeps its own. Avoid it between the two batches of a pair.
- `make clean` removes the demo containers and network. Volumes and images stay.
- After `make down` or a reboot, run `make up`, then give the load generator a few minutes to refill Jaeger before a batch.

## Review a result

`make measure` ends by judging the pair and writing `records/<experiment>/RESULT.md`. Read it from the top: the header names the experiment, both batch ids and both Jaeger commits; the block under it has one line per threshold, a `direction:` line, and `EXPERIMENT PASS` or `EXPERIMENT FAIL`. The direction line reads `direction: variant 7/10 vs baseline 3/10: better`. It says `better` or `worse` when Fisher's p clears the threshold, else `no significant difference at n=10`. Exit code 0 is a judged PASS, 1 a FAIL. Below 10 trials per arm it only ranks the arms. `records/INDEX.md` lists every recorded batch, with the client and model each one recorded.

`make verify` re-scores only the runs under your `RUNS_DIR`. Do not run `judge.py` on the batches attached to a pull request unless you mean to: it rewrites `RESULT.md` and `INDEX.md`.

## Where results land

| Place | Holds | In git |
|---|---|---|
| `runs/` (`RUNS_DIR`) | every batch in full: `stream.jsonl`, `stderr.txt`, one directory per cell | no |
| `records/<experiment>/` | the records of each batch (manifest, cells, scores), and `RESULT.md` | yes |
| `records/INDEX.md` | one row per recorded batch | yes |

`make run` and `make measure` copy each batch's records from `runs/` to `records/<experiment>/` and rewrite `records/INDEX.md`; commit both with your pull request. `make measure` also commits its pair file. `make smoke` never writes `records/`. `judge.py` rewrites `RESULT.md` and `INDEX.md` under `records/` by design: `RESULT.md` is the current answer for that experiment. Records written before 2026-11-23 say `cli`; it is read as `claude`.

## Glossary

- Arm: one side of the comparison, the baseline or the variant, each with its own Jaeger image.
- Trial: one agent run on one scenario, with one scored verdict.
- Batch: the trials of one arm in one run, in `runs/<scenario>/batch-<UTC>/`.
- Pair file: the experiment file `make measure` writes before any trial, naming both images; it is committed first.
- Grader: the model call that reads the agent's mechanism answer and labels it correct, incorrect or unclear.
- Client: the program that runs the agent: `goose`, `claude` (Claude Code) or `codex`.

## Protocol

The published results in this repo were measured with this protocol. A new comparison may use any client and model, provided both arms use the same one (and the same grader).

- Model: `claude-sonnet-5-5`, requested by that full id in `run.model`. Every trial's `model_asserted` in scores.jsonl is the model its stream reported, and the batch aborts after a cell that reports another one.
- Client: the Claude Code CLI with its built-in tools off (`--tools ""`) and only `mcp__jaeger__*` allowed.
- Effort `high`; max turns as the experiment file states (30 in skill-callee-down-cli55).
- 10 trials per arm (`n_per_arm`); with fewer, `bench.py band` and the results table say rank only.
- The arms, images and thresholds are in the experiment file, committed before the first trial; the manifest records `harness_git_sha` and `harness_dirty`. Arms on different images run as consecutive batches against the same fixture.
- A pair is discarded and re-run, not topped up, when:
  - any trial ran on another model;
  - the fixture changed outside the scenario's declared restarts (the trial scores INVALID);
  - the batch stopped before 10 trials (run exits 4 or 6);
  - a trial failed to score (run exits 7);
  - the leak check is red (pre-flight aborts, or the trial scores LEAK);
  - a trial has no cached grade (`bench.py verify` fails).

## Thresholds

| Key | Checks, per test arm |
|---|---|
| `accuracy_pass_min` | the PASS count |
| `fisher_p_max` | PASS only if two-sided Fisher p (`bench.fisher_p`) of baseline vs arm PASS counts is below the value; both arms need the same n |
| exit code | 0 all pass, 1 any fails, 2 refusal: an empty `thresholds` block, or manifests that do not carry one experiment sha256, differ on scenario, scenario version or hash, prompt or system prompt (overlay and image may differ), or have `arm_pin` blocks not matching the argument order |

## Reading results

> [!IMPORTANT]
> Below 10 cells per arm a result is a ranking, not a rate. A rate of 0 or 1 means read the trajectories for a leaky prompt or unfair assertion.

- Every number comes from `bench.py verify`.
- `bench.py band <batch_dir> [--arm A]` (a `$RUNS_DIR` directory; cached grades only) prints the Results table: verdict counts, `err`, `invalid`, `leak`, rate, Wilson 95% CI, medians. `err`, `invalid`, `leak` and abnormal stops count in n, never in PASS. Exit 0 certified, 2 when n is under 10, 3 when the rate is 0 or 1.
- Below it, "Client limits" lists each trial the client may have cut short or squeezed (stopped before a result, compacted, 80% of max_budget_usd used, API retries), or reads "none"; `client_limits` in scores.jsonl, report only.
- Under the table, "Suspect passes" lists each PASS whose trial shows a grounding flag (a cited span id no tool result returned, a flag name or export marker inside a tool result) or whose tool results never matched the scenario's signal, with the trial directory; it reads "none" when empty. These fields (`evidence_unseen`, `tool_result_leak_hits`, `export_marker_hits`) are report only and never change a verdict. `band` and `verify` flag runs with a compaction event (context numbers not comparable). A scenario's `deterministic` value is recorded and shown in `records/INDEX.md`; `band` does not use it. `bench.py power <n_per_arm>` gives the smallest significant variant PASS count (Fisher).

## Scoring

`python3 harness/score.py <trial_dir>` scores the final `result` event's `structured_output` (validated against `verdict-schema.json`).

| Field | Rule |
|---|---|
| `locus` | PASS, PARTIAL or FAIL from service and operation against `pass_rule` |
| `mechanism` | free text graded against `mechanism_truth` by the pinned grader (docs/TUNING.md, Mechanism grader): `correct` PASS, `incorrect` FAIL, `unclear` UNCLEAR (not a PASS); UNGRADED when no cached grade exists and the grader may not be called (every path except the end of `run`) |
| `cascade` | every `cascade_rule.required_any` group must match |
| `verdict` | PASS if locus and mechanism both PASS; UNGRADED if locus is PASS and mechanism is ungraded; PARTIAL if locus is PASS or PARTIAL but mechanism is not; ABSTAIN if the agent set `abstain`; else FAIL |
| INVALID | replaces the verdict when `sandbox_ok` is false, or `fixture_ok` is false (a container outside the scenario's `expected_restarts` restarted, was OOM-killed or changed `StartedAt`) |
| LEAK | replaces the verdict when `leak_hits` is not empty: the answer or any assistant text names a flag, `feature_flag` or `flagd` (docs/RECORD.md, scores.jsonl) |
| no valid `structured_output` | schema-invalid answer, max turns or crash: locus, mechanism and cascade are MISSING, verdict FAIL, `verdict_source` null |

## Export to Phoenix

1. `bench.py run` does this itself after the batch is scored and restored: it sends each trial in the batch's `scores.jsonl` to Phoenix as one OTLP trace and prints `Phoenix <url>/projects/<id>   project <experiment>: one trace per trial` (the id from Phoenix's `/v1/projects`; if that lookup fails, the base URL and `open the project, one trace per trial`) under the `Batch` line. Default endpoint `http://<FIXTURE_HOST>:<PHOENIX_PORT>`, project named after the experiment. Skip it with `run --no-export`. A dry run, a run that exits 1, 5 or 6, and the 3-failure abort never export; a batch whose cells all failed or whose grade failed is exported before it exits 4 or 7, and a failed trial's root span carries the client's error as its status message. If Phoenix is not running (`make phoenix`) or the export is refused, the run prints one WARN with the batch directory and the command below; the exit code and the `Batch` line are unchanged. `make measure` runs both arms with `--no-export` and exports both batches after the judge, a failure only a warning.
   ```bash
   python3 harness/bench.py export <RUNS_DIR>/<scenario>/<batch-id> [--endpoint URL]
   ```
2. Old trajectories never reach the agent: its only route is trajectories landing in the demo's Jaeger. `export` refuses an endpoint on the demo's Jaeger UI port, its OFREP port, 4317 or 4318 (the demo collector), and the pre-flight (stage 3) lists Jaeger's services through the MCP tool `get_services` and stops with a `fix:` line if `jaeger-mcp-evals` is in the store; restart the jaeger container on the fixture host to empty it. If the list cannot be read (an older image without `get_services`) that is a WARN and the run goes on. `preflight.json` records `store_clean`.

> [!IMPORTANT]
> A `records/` copy is refused. Tool spans carry the CLI's own event timestamps; a stream without them (an older CLI) gets an even split of the trial's duration, marked `timestamp.synthetic=true`. Each trace holds one LLM span per model with its token counts, so Phoenix prices it, and the root shows the prompt and the answer.

## What stays out of git

`stream.jsonl`, `stderr.txt` and the per-cell directories carry session identifiers and local paths.
They stay under `RUNS_DIR` (default `runs/`, gitignored) and are never committed; `records/` holds the
checked-in batch files. To share trajectories, attach the `bench.py pack` tarball to a release.
